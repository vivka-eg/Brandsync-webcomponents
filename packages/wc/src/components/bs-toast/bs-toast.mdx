## Overview

A transient status message for confirming the result of an action (e.g. "Files uploaded
successfully.") -- a state-specific icon, a message, and a close button.

This component only renders the toast itself -- it doesn't manage its own visibility, timing, or
stacking. A consumer (typically a small "toast manager" utility) creates one per message and
removes it from the DOM again, whether on a timer or on `bsDismiss`. Figma's spec doesn't show
auto-dismiss timing at all (it's a static visual spec), so this deliberately doesn't invent one.

**When to use**
- Confirming the outcome of an action that just happened (save succeeded, upload failed) without
  interrupting the user's flow.

**When not to use**
- For a response that requires the user to make a decision before continuing -- use `bs-dialog`.
- For persistent, always-visible status -- a toast is inherently transient.

## States

`state` covers `info` (default), `success`, `warning`, and `error` -- each with its own icon
(Info, CheckCircle, Warning, XCircle) and matching container/text tokens. Unlike `bs-snackbar`,
there is no neutral/default state and no reused checkmark glyph across states.

## Overflow

The message wraps to multiple lines rather than truncating -- there's no line-clamp or ellipsis.

## Component API

<Controls of={ToastStories.Default} />

**Customization surface** (see `CONVENTIONS.md` in the repo root for the full convention):
- Slots: default (the message content)
- Shadow parts: `::part(container)`, `::part(icon)`, `::part(message)`, `::part(close)`
- CSS Custom Properties: layout (`--bs-toast-radius`, `--bs-toast-shadow`, `--bs-toast-padding-y`,
  `--bs-toast-padding-x`, `--bs-toast-gap`, `--bs-toast-font-size`, `--bs-toast-line-height`,
  `--bs-toast-close-radius`) plus one surface/text pair per state (`--bs-toast-surface-*`,
  `--bs-toast-text-*`) -- see `bs-toast.css`'s header block for what each aliases to.

## Accessibility

- The toast has `role="status"` and `aria-live` -- `"assertive"` for `state="error"` (interrupts,
  since an error is worth interrupting for), `"polite"` for every other state (announced without
  cutting off whatever a screen reader is already saying). This is a standard toast a11y
  convention, not something Figma's static visual spec addresses one way or the other.
- The icon is `aria-hidden` -- the message text itself is what gets announced.
- The close button always has an accessible name (`aria-label="Dismiss"`), regardless of state.
